# Формат резервной копии Bounty Mapper v4 (чтение v1/v2/v3)

ZIP содержит `manifest.json`, `project.json` и `assets/<номер>.png|jpg|webp`. Пустой каталог `assets/` допустим и присутствует в экспорте даже у проекта без изображений. ZIP-библиотека fflate используется для записи и потоковой распаковки; она не участвует в доменной модели.

`manifest.json`:

```json
{
  "format": "bounty-mapper-project",
  "formatVersion": 4,
  "createdAt": "2026-10-08T00:00:00.000Z",
  "files": [
    { "path": "project.json", "byteSize": 1234, "sha256": "<64 hex characters>" },
    { "path": "assets/0.png", "byteSize": 5678, "sha256": "<64 hex characters>" }
  ]
}
```

Размеры указаны в байтах несжатого файла; SHA-256 вычисляется по его исходным байтам. Manifest перечисляет все файлы содержимого, включая project.json. Сам manifest не хеширует себя; пустой каталог не является файлом содержимого. Лишние файлы, повторяющиеся пути, отсутствующие записи и несовпадающие размеры/контрольные суммы отклоняются.

`project.json` версии 4 имеет ровно пять полей:

- `project`: id, name, contextMd, schemaVersion, revision, createdAt, updatedAt.
- `maps`: все карты проекта с id, projectId, name, notesMd, order, coordinateBounds.
- `imagePlacements`: id, mapId, assetId, x, y, width, height, rotation, order, locked, visible.
- `assets`: metadata оригиналов — id, projectId, mimeType, byteSize, pixelWidth, pixelHeight, checksum, tags, необязательная caption и path файла внутри ZIP. Blob в JSON отсутствует; байты лежат в assets/.
- `regions`: все сохранённые области с id, mapId, vertices[{x,y}], order, number, title, color, fillOpacity, titleCustomized, gmNotes, playerDescription, checks и tags. gmNotes/playerDescription — rich JSON `{type:'doc',content:[...]}`; картинки внутри содержимого используют `{type:'image',attrs:{assetId,alt}}`. Проверка имеет ровно id, condition, ability, result и необязательную dc. Черновики не входят в этот массив.

Экспорт выпускает внешнюю версию 4, импорт принимает версии 1, 2, 3 и 4 с Project.schemaVersion 1. Для v1 строго проверяются прежние четыре поля без regions; затем происходит миграция в regions=[]. У v2 regions обязателен, его прежние восемь полей проверяются строго; затем добавляются пустые документы и массивы checks/tags. v3 требует старые gmNotesMd/playerDescriptionMd/checks/tags: Markdown преобразуется в rich JSON с сохранением поддерживаемого форматирования, исходные Md-поля не остаются второй копией текста. v4 требует документы и titleCustomized. У старых областей titleCustomized определяется сравнением названия с «Область N». Неизвестные версии и поля отклоняются. Формат не содержит маркеров, настроек, камеры, выделения, несохранённых форм, истории undo и дополнительных секретных полей. Экспорт использует явный перечень доменных полей, включая поля проверок. Перед снимком изменённую карточку нужно явно сохранить или отменить.

Проверяются обязательные типы, непустые ID и имена, валидные даты, конечные координаты, положительные размеры, целые revision/order, уникальные ID и пути. Карты и assets принадлежат одному проекту; каждое положение ссылается на существующие map/asset; фон один на карту. Один asset может использоваться несколькими картами. Архив сохраняет и пустые карты, и assets проекта без активных размещений.

Каждая область имеет уникальный id, существующий mapId, положительный целый number, непустой title, hex RGB color и fillOpacity в 0…1. Полигон проходит ту же проверку простоты, площади и вершин, что редактор. Даже архив с правильными контрольными суммами отклоняется при неверной геометрии или ссылках. Разные области могут перекрываться. Суммарно допускается до 2048 областей и 65536 вершин проекта, до 512 вершин в одной области. Координаты по модулю не больше 1e9. Подробнее: [regions.md](regions.md).

Импорт проверяет каталог ZIP до распаковки, поддерживает Store/Deflate, отклоняет ZIP64 и шифрование. Допускаются только два служебных JSON и числовые пути assets/; данные не извлекаются в файловую систему. Распаковка идёт небольшими входными блоками с проверкой фактических размеров результата; заниженные размеры в заголовках не обходят ограничения.

Лимиты: ZIP 128 МиБ, сумма распакованных данных 256 МиБ, изображение 64 МиБ, project.json 4 МиБ, manifest.json 512 КиБ, 512 ZIP-записей, 128 карт, 256 assets. Указанные размеры изображений ограничены 64×1024×1024 пикселями; после проверки SHA-256/MIME/сигнатуры выполняется декодирование и сверка фактических размеров с metadata.

После всех проверок создаётся независимая копия: новый projectId, новые mapId, assetId, placementId, regionId и ID проверок; все ссылки, включая image.assetId внутри обоих текстов, переназначаются одним отображением старых ID в новые. Проект получает суффикс «(копия)», revision 1 и новые даты создания/обновления. Остальные данные и оригинальные изображения сохраняются. Затем копия, включая области и их карточки, записывается одной транзакцией IndexedDB. Ошибка проверки не начинает запись; ошибка транзакции не оставляет частичных данных и не меняет исходные проекты или активный выбор.

Новые поля проверяются даже при верных контрольных суммах: только разрешённые типы узлов/marks/атрибутов rich JSON, безопасные ссылки, существующие image.assetId данного проекта. Предел одного документа: 10000 узлов, глубина 32, 262144 символов текста и 524288 символов JSON. Текст проверки — до 262144 символов; максимум 256 проверок с уникальными ID в области; dc, если задана, — неотрицательное безопасное целое; максимум 256 уникальных непустых тегов до 120 символов. Произвольный HTML и blob URLs не являются форматом текста. Подробности: [region-details.md](region-details.md).

Тесты покрывают round-trip нескольких карт с изображениями и без них, области и их свойства, metadata/байты, независимость копии, согласованный снимок, сохранение последнего текста перед экспортом, отсутствие черновых контуров в архиве, отказ flush, миграцию v1, повреждённые архивы и неизвестные версии, неверную геометрию/ссылки/размеры, ограничения распаковки и позднюю ошибку записи. Браузерные сценарии проверяют скачивание ZIP и импорт реальных изображений и областей в Edge.
