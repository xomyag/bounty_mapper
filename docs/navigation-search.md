# BM-008: navigation, search and project maps

Navigation and search opens the panel; its close button or Escape closes it. Opening a project and reload leave both navigation and the card closed. Regions / Markers tabs change the panel contents while the canvas remains the workspace. The header has no object list. Map management is a dropdown on the right: its closed trigger shows the current map name, the first item is New map, followed by all maps with the current one marked. Each row has three independent buttons: navigate, rename and delete. Actions work without hover using the mouse, Tab/Enter, arrows/Home/End or touch; rename/delete do not switch maps. Escape or an outside click closes the menu. Successful creation opens the new map; renaming updates the menu and search.

Tabs, query and search scope stay visible. Filters and grouping expands extra settings, indicates the number of active extra filters and whether grouping is enabled. Reset filters remains available when settings are collapsed. The map filter changes only results, not the working map; the map management list has been removed from search.

A deleted map/region selected as a filter remains explicitly marked Map deleted / Region deleted and yields no results until changed or reset. It does not masquerade as All maps / Any binding or switch the working map.

## Search and representations

`src/domain/navigation.ts` implements search/grouping without React, Konva or IndexedDB. The index comes from one readonly snapshot of the current project's maps/regions/entities/markerPlacements, without reading blobs. A successful shared-revision write refreshes it. Unsaved cards do not replace saved search results; navigation uses the common draft dialog. Unused Entity records without placements are not listed; the library remains a later stage.

Search matches a substring in the name, region number or individual tag after NFKC normalization and lowercasing. Scope limits candidates to the current map or whole project. Map, tags, type, status and linked region combine with AND. Selected tags explicitly use Any selected (OR, default) or All selected (AND); tag filters compare entire tags case-insensitively. Regions do not use type/status filters. Status choices are valid for the selected type; with all types, the combined values have localized display labels.

Regions group by nothing, map or tag, including Untagged. Markers group by nothing, map, type, status or linked region. The last option includes No region; every regionId provides a representation of the same placement. The count is unique results before grouping; repeated row buttons reference one marker.id. Grouping does not copy objects into project data.

Each tab's query, scope, filters, tag logic and grouping survive tab switching and panel closing. Reset filters clears query and filters for the active tab and restores Current map scope while retaining grouping. These settings live in page memory and start afresh on reload.

## Navigation and viewport

`RegionSession.navigate(NavigationTarget)` is the shared entry point for search, ordinary map switching and links between cards. It uses existing unsaved-changes confirmation. Navigation is temporarily unavailable during writing/image preparation, drawing and vertex editing. Continue editing or a write failure retains the source object, text and camera. A target-map read/decode failure also retains the source map and draft.

For another map, its image, regions, entities and placements are read and its background decoded before changing live state. The prepared map and object are accepted together: selectedId/cardId or selectedMarkerId/markerCardId, the appropriate BM-006 mode and one centering request. No additional card panel is created. Ordinary canvas click/tap opens without centering. Selecting the same result again centers it while retaining an already open draft.

`ViewportMemory` keeps cameras by mapId in App memory, outside the project document. Ordinary switching restores the last view; a first-opened map uses fit. Since BM-010, replacing/removing a background and retrying its write preserve the camera; the background no longer invalidates the viewport. For a new image on an already open map, Show entire map is an explicit action. Search centers the region label anchor or marker.x/y over the restored camera without changing scale. React applies the new camera before paint, without an intermediate fit. Resizing, field changes, writing, closing panels and grouping neither reset the camera nor recreate the canvas. Decoded backgrounds are cached for up to eight assets; an evicted background is prepared before navigation. Reload opens the first map by order and fits it anew. Geometry undo, as before, belongs to the current map; switching maps clears history.

## Storage and compatibility

BM-008 left Project/Map/Entity/MarkerPlacement and **IndexedDB 7 / Project.schemaVersion 1 / ZIP 6** unchanged. Map creation/renaming writes maps and shared Project revision in a single conflict-checked transaction; a late error leaves no partial map. Names are 1…512 characters, with up to 128 maps (the existing ZIP limit); order increments. An empty map uses bounds (0,0,1000,1000) for independent coordinates; a background upload sets its dimensions. Objects are never created automatically. All maps, fields and images enter the existing archive snapshot. UI filters, grouping and cameras are not exported.

Deletion requires a separate confirmation showing the map name and contents to be removed; initial focus is Cancel. Cancel and errors retain data and viewport. One revision-checked transaction deletes Map, its Region/MarkerPlacement/ImagePlacement records and only its assets no longer referenced by other map backgrounds, region notes/descriptions or any project Entity description. Entities remain even without placements, as in BM-007. The next map by order (or first remaining map) and its decoded background are prepared before deletion. After confirmed writing, it is accepted with its remembered viewport and a closed card; deleting another map leaves the current camera/card unchanged. Deleting the last map shows an empty workspace with Create map. Map deletion is not geometry-undoable. Creating, renaming and deleting require finishing operations and saving/canceling the card; switching resolves drafts through the existing dialog.

## Shared tag suggestions

Regions and markers share `TagsInput` and the current project's catalog: tags from all regions, all Entity records and usage history. An empty field offers up to five recent tags; typing offers up to five case-insensitive substring matches, excluding the current card's tags. Recent matches come first. Comparison uses trim, NFKC and lowercasing; display spelling comes from the catalog, while a new tag keeps its first entered spelling. Saving a card also removes old duplicates in its tag array without changing other fields. Without history, the catalog is sorted predictably by spelling. Arrows select suggestions; Enter adds the active suggestion or a new tag; Escape closes the list. Events neither save/close the card nor control the map. Selection clears the input; suggestions are also buttons.

History is UI metadata in `settings["tagHistory:<projectId>"]`, up to 512 recent unique tags; other existing tags remain in the catalog. Saving the card writes its tags and history **in one transaction**; tags later in the array count as more recently used. Errors, draft cancellation and geometry writes leave history unchanged. Reload restores it. IndexedDB remained 7 because the existing settings store is used; a missing key means empty history and needs no structural migration. Project.schemaVersion 1 and ZIP 6 stayed unchanged. Tags are archived; local suggestion history, like other user settings, is not. An imported independent copy starts with a predictable catalog of its tags and empty independent history without changing the original's history.

IndexedDB 6→7 and ZIP 5→6 migrations remain: old regionId becomes regionIds[], or [] when absent. Deleting a region removes only its ID; undo restores it. Import remaps all map, region, entity, placement and image IDs, including every binding.

Accepted BM-007, legacy binding and archive checks remain. Manual steps are in [README](../README.md).
